# StoryFlow AI 项目介绍

## 项目定位

StoryFlow AI 是一个基于 Multi-Agent Runtime 的 AI 漫剧自动生成平台。用户只需输入一段创意描述（如"胖子甄大卫逆袭校花莲花的故事"），系统通过 7 个 AI Agent 串行协作，自动完成剧本生成、角色设计、分镜编排、图片生成、图生视频、配音合成、视频导出全流程，最终输出可播放的 MP4 漫剧视频。

核心设计原则：**全部使用云端 API，零本地 GPU 依赖**。图片走 DashScope/DALL-E API，语音走 DashScope TTS API，图生视频走 Kling/Runway API，可部署在任何一台普通服务器上。

## 7 个 Agent

| # | Agent | 职责 | 输入 | 输出 |
|---|-------|------|------|------|
| 1 | **Script Agent** | 剧本生成 | 用户创意 (prompt + genre) | 剧情大纲 + 角色设定 + 分集剧本 |
| 2 | **Character Agent** | 角色视觉设计 | 剧本中的角色描述 | AppearanceCard (hair/body/cloth/face) |
| 3 | **Storyboard Agent** | 分镜编排 | 剧本 + 角色外观 | 逐场景 prompt/camera/duration/dialogue |
| 4 | **Image Agent** | 图片生成 | 分镜 prompt + 角色特征 | 1024x1024 图片 (逐场景) |
| 5 | **Image-to-Video Agent** | 图生视频 | 每张场景图片 | 3-5 秒动态视频 (逐场景) |
| 6 | **Voice Agent** | 语音合成 | 对话文本 + 角色性别 | 语音音频 (逐场景) |
| 7 | **Video Agent** | 视频合成 | 视频 + 音频 + 字幕 | 最终 MP4 |

数据流：

```
Script (剧本) → Character (角色)
                    ↓
              Storyboard (分镜)
               ↓              ↓
           Image (图片)    Voice (语音)
               ↓
        Image-to-Video (动态视频)
               ↓              ↓
              Video (最终合成 ← 音频 + 视频)
```

## 5 类 Adapter

Adapter 层隔离了所有外部 API 的差异，每类 Adapter 支持多个 Provider，统一接口，方便切换和扩展。

| Adapter 类型 | 职责 | Provider |
|-------------|------|----------|
| **LLM Adapter** | 大语言模型调用 | OpenAI / Qwen / DeepSeek / Claude (任意 OpenAI 兼容 API) |
| **Image Adapter** | 文生图 | DashScope (通义万相) / DALL-E 3 |
| **I2V Adapter** | 图生视频 | Kling / Runway |
| **Voice Adapter** | 语音合成 | DashScope TTS |
| **Video Adapter** | 视频合成 | FFmpeg (本地) |

### Mock 降级策略

未配置某类 API 时系统不会报错，而是自动降级为合理的替代方案：

| API 未配置 | 降级行为 | 说明 |
|-----------|---------|------|
| Image API | 生成纯色占位图 + 场景文字标注 | 流程可完整跑通 |
| I2V API | FFmpeg 将静态图合成为视频 (Ken Burns 缩放效果) | 视频仍然可播放 |
| TTS API | 生成静默音频文件 | 视频时长正常，无声音 |

## Workflow DSL v2.0

工作流通过 YAML 定义，Planner 读取后生成 Runtime 执行步骤：

```yaml
name: comic
version: "2.0"
steps:
  - name: script
    agent: script_agent
    retry: { max_attempts: 3, backoff: exponential }

  - name: character
    agent: character_agent
    depends_on: [script]

  - name: storyboard
    agent: storyboard_agent
    depends_on: [script, character]

  - name: image
    agent: image_agent
    depends_on: [storyboard, character]
    parallel: per_scene

  - name: image_to_video
    agent: image_to_video_agent
    depends_on: [image]
    parallel: per_scene

  - name: voice
    agent: voice_agent
    depends_on: [storyboard]
    parallel: per_scene

  - name: video
    agent: video_agent
    depends_on: [image_to_video, voice]
```

## Runtime 基础设施

当前已实现的 Runtime 能力：

| 能力 | 说明 |
|------|------|
| **Hook 事件系统** | 14 种生命周期事件，支持 Logger / QualityGate / Langfuse Handler 链式处理 |
| **Memory 记忆系统** | 4 层 Memory (working / session / conversation / long-term) + CharacterMemoryService |
| **Skill 技能引擎** | YAML 定义每个 Agent 的 I/O Schema、约束规则，Runtime 自动加载和校验 |
| **Session 会话管理** | 会话状态管理 + 超时恢复 |
| **A2A Message Bus** | Agent 间通信，支持 InMemory 和 Redis Stream 两种传输层 |
| **MCP 协议** | 消息封装 (Envelope) + 路由 (Router) + 校验 (Validator) |
| **Execution 调度器** | LLM / Tool / GPU 线程池隔离，并发控制 |
| **Quality Gate** | 每个 Agent 专用校验器，不合格自动重试 |
| **Langfuse 可观测性** | 配置即启用，全链路 Trace |

## V1.5 迭代路线图

### 当前状态与目标

当前系统已经是一个工程质量很高的 Workflow Multi-Agent 系统。Runtime、EventBus、Memory、Retry、Trace 等基础设施已具备，Agent 也实现了解耦。但它还不是一个「会思考、会协商、会反思」的 Multi-Agent 系统。

V1.5 的核心目标：**不增加业务 Agent，而是让 Runtime 增加七项核心能力，让现有 Agent 建立真正的协作关系。**

### 整体架构升级

```
当前:  Workflow → Agent → Result

升级为:
                    Director Runtime
                            │
                            ▼
                    Planner Runtime
                            │
                            ▼
                 Dynamic Workflow Runtime
                            │
                            ▼
                    Reflection Runtime
                            │
                            ▼
        Prompt Runtime ←→ Memory Graph
                            │
                            ▼
                    Quality Runtime
                            │
                            ▼
                    Retry Runtime
                            │
                            ▼
                     Agent Message Bus
                            │
                            ▼
 Script  Character  Storyboard  Image  I2V  Voice  Video
```

### 七大 Runtime 子系统

#### 1. Reflection Runtime (最重要)

每一步 Agent 执行后，Reflection Runtime 自动总结该步骤的优劣，生成结构化反馈：

```json
{
  "step": "image",
  "good": ["人物一致性保持良好"],
  "bad": ["背景风格与前一张不统一"],
  "suggestion": ["增加古风建筑描述", "参考第 3 张图的色调"]
}
```

Suggestion 注入到 Prompt Runtime 中，下一次生成时自动改进。流程：Image → Reflection → Quality → Director → Retry → Image (带着反馈重做)。

#### 2. Prompt Runtime

所有 Prompt 不再固定写死，而是由 Prompt Runtime 动态构建：

```
Template (基础模板)
  + Character Memory (角色当前状态)
  + World Memory (世界观设定)
  + Timeline (剧情时间线)
  + Quality Suggestion (反思建议)
  + Director Instruction (导演指令)
        ↓
   Prompt Builder → 最终 Prompt
```

效果：Prompt 越来越长、越来越准确。例如从简单的"少女站在河边"演变为"少女, 黑长发, 第一章衣服, 第三章受伤状态, 古代河边, 避免现代建筑, 保持上一张画风"。

#### 3. Memory Graph (非常重要)

从静态 JSON 属性升级到带时间线的图结构记忆：

```
林晓
  ├─ 穿白衣 (第 1-2 章)
  ├─ 第二章受伤
  ├─ 第三章换红衣
  ├─ 第四章恢复
  └─ 第五章黑化
```

Runtime 根据当前时间线自动查询角色应处于的状态，Image Agent 永远不会画错角色外观。

#### 4. Director Runtime (真正导演)

当前 Director 只是 if-else 超时重试逻辑。升级后 Director 观察整个 Pipeline，诊断失败根因：

```
Image 失败 → Director 诊断:
  → Prompt 太简单？ → 让 Storyboard 重写分镜
  → 角色描述不够？ → 让 Character 补充
  → 模型问题？ → 切换 Provider
  → 偶发错误？ → 直接重试
```

核心区别：不是"Image 重试 N 次"，而是"找到根因，指向正确的 Agent 重做"。

#### 5. Agent Conversation (Agent Bus 协作)

引入 Agent Message Bus，Agent 之间像团队一样讨论和协商：

```
Director:  ImageAgent, 为什么失败？
Image:     人物不像。
Director:  Storyboard, Prompt 是不是太简单？
Storyboard: 建议增加 "长发" "白裙" "夏日"。
Director:  Image, 重新画。
```

#### 6. Dynamic Workflow (动态工作流)

Planner 根据故事特征运行时动态生成 Workflow，而非固定 YAML：

- 故事很长 → 自动增加 Summary Agent
- 人物很多 → 自动增加 Character Review Agent
- 有战斗场景 → 自动增加 Action Choreography Agent

#### 7. Model Router (智能模型路由)

根据任务类型自动选择最优模型/Provider：

| 任务类型 | 推荐模型 | 选择依据 |
|---------|---------|---------|
| 剧本生成 | Claude | 长文本创意能力强 |
| Prompt 构建 | Gemini | 多模态理解 |
| 图片生成 | Flux / DALL-E 3 | 视觉质量 |
| 视频生成 | Veo3 / Kling | 动态质量 |
| 语音合成 | FishSpeech / DashScope TTS | 语音自然度 |

根据速度、价格、质量三个维度自动选优。

### 精力分配

| 方向 | 比例 |
|------|------|
| Runtime 核心能力 (Reflection/Prompt/Memory/Director/Retry/Quality/Trace) | 40% |
| Director Runtime (根因诊断 + 跨 Agent 协调) | 25% |
| Quality Pipeline (独立 Checker) | 20% |
| Agent 改进 (接入新 Runtime 能力) | 10% |
| 前端 | 5% |
