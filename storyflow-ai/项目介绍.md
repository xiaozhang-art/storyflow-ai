# StoryFlow AI 项目介绍

## 项目定位

StoryFlow AI 是一个基于 Multi-Agent Runtime 的 AI 漫剧自动生成平台。用户只需输入一段创意描述（如"胖子甄大卫逆袭校花莲花的故事"），系统通过 7 个 AI Agent 串行协作，自动完成剧本生成、角色设计、分镜编排、图片生成、图生视频、配音合成、视频导出全流程，最终输出可播放的 MP4 漫剧视频。

核心设计原则：**全部使用云端 API，零本地 GPU 依赖**。图片走 DashScope/DALL-E API，语音走 DashScope TTS API，图生视频走 Kling/Runway API，可部署在任何一台普通服务器上。

## 7 个 Agent

| # | Agent | 职责 | 输入 | 输出 |
|---|-------|------|------|------|
| 1 | **Script Agent** | 剧本生成 | 用户创意 (prompt + genre) | 剧情大纲 + 角色设定 + 分集剧本 |
| 2 | **Character Agent** | 角色视觉设计 | 剧本中的角色描述 | AppearanceCard (hair/body/cloth/face) |
| 3 | **Storyboard Agent** | 分镜编排 | 剧本 + 角色外观 | 逐场景 prompt/camera/duration/dialogue |
| 4 | **Image Agent** | 图片生成 | 分镜 prompt + 角色特征 | 1024x1024 图片 (逐场景) |
| 5 | **Image-to-Video Agent** | 图生视频 | 每张场景图片 | 3-5 秒动态视频 (逐场景) |
| 6 | **Voice Agent** | 语音合成 | 对话文本 + 角色性别 | 语音音频 (逐场景) |
| 7 | **Video Agent** | 视频合成 | 视频 + 音频 + 字幕 | 最终 MP4 |

数据流：

```
Script (剧本) → Character (角色)
                    ↓
              Storyboard (分镜)
               ↓              ↓
           Image (图片)    Voice (语音)
               ↓
        Image-to-Video (动态视频)
               ↓              ↓
              Video (最终合成 ← 音频 + 视频)
```

## 5 类 Adapter

Adapter 层隔离了所有外部 API 的差异，每类 Adapter 支持多个 Provider，统一接口，方便切换和扩展。

| Adapter 类型 | 职责 | Provider |
|-------------|------|----------|
| **LLM Adapter** | 大语言模型调用 | OpenAI / Qwen / DeepSeek / Claude (任意 OpenAI 兼容 API) |
| **Image Adapter** | 文生图 | DashScope (通义万相) / DALL-E 3 |
| **I2V Adapter** | 图生视频 | Kling / Runway |
| **Voice Adapter** | 语音合成 | DashScope TTS |
| **Video Adapter** | 视频合成 | FFmpeg (本地) |

### Mock 降级策略

未配置某类 API 时系统不会报错，而是自动降级为合理的替代方案：

| API 未配置 | 降级行为 | 说明 |
|-----------|---------|------|
| Image API | 生成纯色占位图 + 场景文字标注 | 流程可完整跑通 |
| I2V API | FFmpeg 将静态图合成为视频 (Ken Burns 缩放效果) | 视频仍然可播放 |
| TTS API | 生成静默音频文件 | 视频时长正常，无声音 |

## Workflow DSL v2.0

工作流通过 YAML 定义，Planner 读取后生成 Runtime 执行步骤：

```yaml
name: comic
version: "2.0"
steps:
  - name: script
    agent: script_agent
    retry: { max_attempts: 3, backoff: exponential }

  - name: character
    agent: character_agent
    depends_on: [script]

  - name: storyboard
    agent: storyboard_agent
    depends_on: [script, character]

  - name: image
    agent: image_agent
    depends_on: [storyboard, character]
    parallel: per_scene

  - name: image_to_video
    agent: image_to_video_agent
    depends_on: [image]
    parallel: per_scene

  - name: voice
    agent: voice_agent
    depends_on: [storyboard]
    parallel: per_scene

  - name: video
    agent: video_agent
    depends_on: [image_to_video, voice]
```

## Runtime 基础设施

V1.5 Runtime (V5.0) 已完成的子系统：

| 子系统 | 说明 |
|--------|------|
| **Director (决策大脑)** | LLM 驱动的 5-决策大脑 (PROCEED/RETRY/ROLLBACK/REWRITE_PROMPT/SKIP)，读取全部产出物分析后做出智能决策，无 LLM 时降级为规则引擎 |
| **WorkflowEngine (管线编排)** | 集成 Director、A2A、StoryMemory 的管线引擎，每步自动注入记忆上下文和 A2A 消息，执行后触发 Director 决策循环 |
| **AgentConversationBus (A2A 通信)** | 结构化富上下文消息传递，携带角色档案、场景数据、生成统计、产出物引用、约束模板、质量反馈 |
| **StoryMemory (统一记忆)** | 7 维记忆 (Scene/Visual/Style/World/Character/Timeline/Meta)，WorkflowEngine 每步自动查询和存储 |
| **MemoryManager (4 层记忆)** | Working / Session / Conversation / Long-term 四层层级，支持 TTL 自动过期 |
| **MemoryGraph (时间线记忆图)** | 时间线感知的角色状态追踪，角色外观/状态随剧情推进自动演变 |
| **PromptRuntime (动态 Prompt)** | 动态组装基础模板 + 角色记忆 + 世界观 + 时间线 + 反思建议 + 导演指令 |
| **ReflectionRuntime (反思)** | 每步生成 good/bad/suggestion 结构化反馈，注入后续步骤 Prompt |
| **ModelRouter (模型路由)** | 按任务类型、速度、价格、质量智能选择最优模型/Provider |
| **QualityEngine (质量引擎)** | 6 个 Agent 专用校验器，不合格自动触发 Director 重试决策 |
| **RetryEngine (重试引擎)** | 策略化重试（指数退避、 Director 驱动、持久性失败 SKIP） |
| **TraceRuntime (链路追踪)** | 全链路执行追踪，支持 Langfuse 可观测性 |
| **AdapterRegistry (适配器注册)** | 统一注册 LLM/Image/Voice/I2V/Video 适配器，支持 Mock 降级 |
| **EventBus (事件总线)** | 14 种生命周期事件，支持链式 Handler 处理 |
| **Session (会话管理)** | 会话状态管理 + 超时恢复 |

### 七大 Runtime 子系统

#### 1. Reflection Runtime ✅ 已完成

每一步 Agent 执行后，Reflection Runtime 自动总结该步骤的优劣，生成结构化反馈：

```json
{
  "step": "image",
  "good": ["人物一致性保持良好"],
  "bad": ["背景风格与前一张不统一"],
  "suggestion": ["增加古风建筑描述", "参考第 3 张图的色调"]
}
```

Suggestion 注入到 Prompt Runtime 中，下一次生成时自动改进。流程：Image → Reflection → Quality → Director → Retry → Image (带着反馈重做)。

#### 2. Prompt Runtime ✅ 已完成

已实现并接入 Image Agent、Storyboard Agent、Character Agent。所有 Prompt 不再固定写死，而是由 Prompt Runtime 动态构建：

```
Template (基础模板)
  + Character Memory (角色当前状态)
  + World Memory (世界观设定)
  + Timeline (剧情时间线)
  + Reflection Suggestions (反思建议)
  + Director Instruction (导演指令)
        ↓
   Prompt Builder → 最终 Prompt → Agent 使用
```

效果：Prompt 越来越长、越来越准确。例如从简单的"少女站在河边"演变为"少女, 黑长发, 白色中式长裙, 古代河边, 避免现代建筑, 保持上一张画风"。

#### 3. MemoryGraph (时间线记忆图) ✅ 已完成

从静态 JSON 属性升级到带时间线的图结构记忆：

```
林晓
  ├─ 穿白衣 (第 1-2 章)
  ├─ 第二章受伤
  ├─ 第三章换红衣
  ├─ 第四章恢复
  └─ 第五章黑化
```

Runtime 根据当前时间线自动查询角色应处于的状态，Image Agent 永远不会画错角色外观。MemoryGraph 集成于 StoryMemory，WorkflowEngine 每步执行前自动查询。

#### 4. Director Runtime (决策大脑) ✅ 已完成

Director 已从 if-else 超时重试逻辑重写为真正的 LLM 决策大脑。Director 观察整个 Pipeline 的全部产出物，通过 LLM 分析做出 5 种智能决策：

```
Image 失败 → Director 诊断 (读取全部 Artifact):
  → Prompt 太简单？ → REWRITE_PROMPT (LLM 重写 prompt)
  → 角色描述不够？ → ROLLBACK (回退到 Character)
  → 模型问题？     → RETRY (重试当前步骤)
  → 偶发错误？     → RETRY (含重试上下文)
  → 持久性失败？   → SKIP (跳过，避免死循环)
```

核心区别：不是"Image 重试 N 次"，而是"找到根因，指向正确的决策"。无 LLM 时自动降级为规则引擎。

#### 5. Agent Conversation (A2A 结构化通信) ✅ 已完成

AgentConversationBus 升级为结构化富上下文传递，Agent 之间通过携带完整上下文的结构化消息协作：

```
[AgentConversationBus]
  → 角色档案 (Character Profiles)
  → 场景数据 + 角色-场景映射
  → 生成统计 (Generation Stats)
  → 产出物引用 (Artifact References)
  → 约束模板 (script→character: 外观四维度 / character→storyboard: 一致性)
  → 动态约束 (按状态注入: 角色一致性、集数检查)
  → 质量反馈 (错误、警告、修复建议)
```

WorkflowEngine 在每步执行前自动将 A2A 消息注入 Agent 状态。

#### 6. Dynamic Workflow (动态工作流) ✅ 已完成

WorkflowEngine 通过 Director 实现动态管线控制（INSERT_STEP 决策可插入自定义修复函数），结合 Workflow DSL v2.0 YAML 定义，支持按场景粒度的并行执行。

#### 7. Model Router (智能模型路由) ✅ 已完成

根据任务类型自动选择最优模型/Provider：

| 任务类型 | 推荐模型 | 选择依据 |
|---------|---------|---------|
| 剧本生成 | Claude / GPT-4o | 长文本创意能力强 |
| Prompt 构建 | Gemini / Qwen | 多模态理解 |
| 图片生成 | DashScope (通义万相) / DALL-E 3 | 视觉质量 |
| 图生视频 | Kling / Runway | 动态质量 |
| 语音合成 | DashScope TTS (CosyVoice) | 语音自然度 |

根据速度、价格、质量三个维度自动选优。

## 核心设计

### Director 5-决策循环

V1.5 Runtime 的核心是 Director 驱动的决策循环。每一步 Agent 执行完毕后，WorkflowEngine 触发以下流程：

1. **产出物收集** — ArtifactManager 收集当前步骤的全部产出物
2. **记忆查询** — StoryMemory 根据当前管线位置查询相关记忆上下文
3. **A2A 消息构建** — AgentConversationBus 组装结构化上下文（角色档案、场景数据、约束模板、质量反馈）
4. **Director 分析** — Director 接收（产出物摘要 + 管线位置 + 重试上下文 + 决策历史），通过 LLM 分析做出决策
5. **决策执行** — PROCEED → 下一步 / RETRY → 重试 / ROLLBACK → 回退 / REWRITE_PROMPT → 重写后重试 / SKIP → 跳过

无 LLM 时 Director 自动降级为规则引擎，保证系统在极端情况下仍可运行。

### A2A 结构化消息传递

Agent 之间的通信不再是纯文本摘要，而是携带完整上下文的结构化消息。每个 A2A 消息包含：
- **Character Profiles** — 当前角色的完整视觉档案
- **Scene Data** — 场景描述与角色-场景映射
- **Constraints** — 按转换类型的模板约束（如 script→character 要求外观四维度）+ 按状态的动态约束（如角色一致性检查）
- **Feedback** — 上游质量门禁的错误、警告和修复建议

WorkflowEngine 在每个 Agent 执行前自动注入 A2A 消息，确保每个 Agent 都能看到完整的上下文。

### 统一架构

V1.5 Runtime 是唯一的运行时引擎，无需环境变量切换。core.py (V5.0) 负责自动组装 Director + ArtifactManager + ConversationBus + StoryMemory + EventBus，所有外部能力通过 AdapterRegistry 统一管理。
